# OmniSignal 最小威胁模型

## 1. 保护对象与信任边界

保护对象包括：来源授权范围、凭证、原始/标准化数据、删除状态、连接器检查点、审计日志、ConnectorSpec 和 MetricSpec。

信任边界分为五层：外部来源 → 普通连接器/浏览器连接器/Hook runner → 核心接入接口 → 存储与队列 → 查询、导出和可选处理插件。外部内容与连接器输出默认不可信；Hook runner 风险最高，必须独立进程或容器。

## 2. 主要风险和控制

| ID | 风险场景 | 主要后果 | 最小控制 | 验证方式 |
| --- | --- | --- | --- | --- |
| T01 | 外部文本包含 Prompt Injection | 修改配置、诱导工具调用或泄露数据 | 文本只进入数据字段；核心链不调用 LLM；插件使用固定 schema 且无工具权限 | 恶意夹具不得改变任务、URL 或权限 |
| T02 | 数据投毒、广告、水军或异常峰值 | 指标和标准化结果失真 | 来源追踪、重复检测、批次/字段异常阈值、隔离区，不自动作业务结论 | 注入重复和极端值，异常批次被隔离 |
| T03 | 多收个人信息 | 隐私泄露和不必要留存 | 字段白名单、禁止字段、脱敏、最短保留、受限导出 | 夹具中的邮箱/Token/位置字段不落库 |
| T04 | Token/Cookie 进入 Git、日志或快照 | 账号被接管 | 只存 secret reference；请求头和异常脱敏；提交前 secret scan | 使用假 Token 跑失败流程，日志不得出现原值 |
| T05 | 连接器越过允许域名、账号或租户 | 越权采集 | 精确目标允许列表、重定向后复核、租户作用域、默认拒绝 | 越界 URL、重定向和租户 ID 被拒绝 |
| T06 | SSRF 或本地文件读取 | 访问内网服务或主机文件 | 禁止 `file://`；阻止回环/链路本地/私网地址；DNS 与重定向复核 | 访问 localhost、私网 IP、metadata 地址均失败 |
| T07 | 页面/响应过大、压缩炸弹或无限滚动 | 内存、磁盘或浏览器耗尽 | 响应体、解压比、页数、时间和滚动上限；独立资源配额 | 超限夹具被中止且其他连接器继续 |
| T08 | Webhook 重放或伪造 | 重复或伪造数据 | 签名校验、时间窗、nonce/幂等键；签名秘密仅在 runner | 重放事件只处理一次，错误签名拒绝 |
| T09 | Hook/补丁失效或被利用 | 进程逃逸、错误数据、系统不稳定 | 独立低权限 runner、无宿主敏感目录、输出 schema、熔断、kill switch | runner 崩溃/漂移只停自身 |
| T10 | Schema 漂移被当作正常数据 | 静默缺失或字段错位 | schema 指纹、契约校验、未知字段隔离、人工确认后升级 | 字段删改触发 quarantine 和告警 |
| T11 | 401/403 后程序持续尝试 | 封号、越权或请求风暴 | 立即暂停；禁止账号池和自动换身份；人工恢复 | 固定响应使连接器进入 paused |
| T12 | 429/5xx/断网导致丢失或重复 | 数据不完整 | 有界重试、退避、检查点、幂等键和死信记录 | 中断恢复后三次重放无重复 |
| T13 | 删除未级联或备份恢复后复活 | 已撤回数据再次出现 | 删除清单、派生级联、备份到期、恢复后重放删除 | 执行 data_policy 中的固定删除场景 |
| T14 | 跨来源或跨产品权限串线 | 数据被错误查看/删除 | 来源作用域键、角色权限、审计、连接器专用账号 | 同 ID 不同来源互不影响 |
| T15 | UI 展示原始 HTML/公式导致 XSS | 操作员会话被窃取 | 默认纯文本渲染、HTML 清洗、CSP、下载隔离 | 恶意 HTML 只显示为文本 |
| T16 | 第三方依赖或更新被植入 | 构建/运行环境受控 | Gate 2 的许可证、锁版本、SBOM、漏洞扫描、升级回滚 | 构建只使用锁定依赖并留清单 |
| T17 | 审计日志泄露正文或秘密 | 二次泄密 | 结构化事件、字段级脱敏、禁止请求头/正文、访问受控 | 假密钥和敏感文本不出现在审计中 |
| T18 | 指标缺少合法分母仍输出百分比 | 产生误导性“全网占比” | MetricSpec 强制分子、分母、覆盖范围；缺失即返回 unavailable | 缺分母夹具拒绝生成百分比 |

## 3. 风险处置顺序

必须先处理：T04 凭证泄露、T05/T06 越界访问、T09 Hook 隔离、T13 删除失败、T14 权限串线。其次处理资源耗尽、schema 漂移和数据投毒。业务解释偏差不由平台自动修正，平台只暴露来源、覆盖范围和质量状态。

## 4. 自动停用条件

出现以下任一情况时只停对应连接器：401/403、目标不在允许列表、授权过期、连续 schema 校验失败、Hook 目标签名改变、敏感字段命中、异常数据比例越线、请求预算耗尽或 kill switch 被触发。不得通过更换账号、指纹伪装、代理池或自动寻找新接口继续运行。

## 5. Gate 1 验收映射

- 字段来源和用途：`source_registry.yaml > field_catalog`。
- 每个来源允许字段与授权：`sources[].field_allowlist / authorization_basis`。
- 保留、删除和撤回：`data_policy.md` 第 5 节。
- 谁能访问：登记表 `roles` 与 `data_policy.md` 第 3 节。
- Prompt Injection、数据投毒、个人信息：T01、T02、T03。
- 删除级联验证：`data_policy.md` 第 8 节，Gate 3 实现自动化测试。
- 紧急停用和故障隔离：T09、T11 及第 4 节。

Gate 1 只冻结政策、登记格式和测试预期；没有存储骨架前，不假装已经完成运行级验证。
