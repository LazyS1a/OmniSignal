# 通过 Nova 复用视觉模型进行灵感分析

Omni 可以把单张图片分析任务交给 Nova 的内部网关。模型服务商凭据留在 Nova；Omni 只持有这个内部接口的服务令牌。模型名称从实际完成的任务返回，不在 Omni 中写死为 GPT-4o。

## 配置

在 Omni 服务端配置以下环境变量，重启工作台进程生效：

| 变量 | 用途 |
| --- | --- |
| `OMNISIGNAL_WORKBENCH_ANALYSIS_BACKEND=nova` | 启用 Nova 网关；未设置时保持原来的直接模型模式 |
| `OMNISIGNAL_WORKBENCH_NOVA_BASE_URL` | Nova 的 HTTPS 站点地址，只包含协议、域名和可选端口，不附带路径 |
| `OMNISIGNAL_WORKBENCH_NOVA_TOKEN` | Nova 内部分析接口的专用服务令牌，不是模型厂商密钥 |
| `OMNISIGNAL_WORKBENCH_MODEL_DAILY_REQUEST_LIMIT` | Omni 每个 UTC 日最多发起的分析次数；默认 0 禁用 |
| `OMNISIGNAL_WORKBENCH_WORKER=true` | 启用后台任务执行 |

不要把令牌放进前端环境变量、Git、URL 查询参数或日志。Nova 的网关需要先完成部署和令牌配置。启用 Nova 模式不要求在 Omni 保存 `OMNISIGNAL_WORKBENCH_MODEL_API_KEY`。

工作台配置查询不发起网络请求。首次显示“连接已配置”只表示本机配置完整；提交任务时才查询 Nova 的 `/api/internal/inspiration-analysis/config`，核验实际就绪状态。Nova 未就绪不会提交图片，Omni 的保守请求额度仍可能计入一次。

## 使用与输出

1. 在“待处理”打开素材；管理员核实并保存该图片的模型分析权限。
2. 点击“分析这张图片”。只发送当前图片、图片 ID、版本号、原文件哈希、最多 500 字标题和 2000 字项目说明。
3. 图片在发送前转为最大边 1024 像素的 JPEG，且不超过 1 MiB。不会上传其他素材或整个知识库。
4. 结果显示实际模型名称、基础分类及配色、字体、构图、信息层级、视觉手法、可借鉴方法、适用场景和不确定项。
5. 人工核对后可“采用建议填写”；这只填充已有审核表单。设计拆解保存在分析记录中，不自动成为人工审核结论，也不自动发布给 Nova 的知识库。

所有结果仍是建议。没有人工授权就不会发起模型分析；分析期间修改素材或权限，会使旧结果过期。当前处理单位是一张图，多图项目汇总不包含在这个接口版本中。

## 队列、额度与故障处理

- Omni 本地任务 ID 对应稳定的远程 `request_id`，网关可以据此去重。
- 客户端只提交一次 POST，每次等待窗口最多 100 秒。请求 ID 在提交前持久化，收到回执就立即保存远端任务 ID。
- 网络错误或等待超时会进入“等待 Nova 原任务结果”。后台每轮等待后至少间隔 15 秒，通过原任务 ID 只读同步；若 POST 回执丢失，则用 `/jobs/by-request/{request_id}` 找回任务。不会再次 POST，也不会再扣本地请求额度。进程重启后仍按这个规则恢复。
- 等待同步期间再次点击提交仍返回同一个任务。只有远端明确完成、失败等终态后，才允许明确创建新分析任务；重试可能再次计费。
- 查询持续返回 404 或网关不可访问时，保留“待确认”并阻止为同一素材版本新建任务，需要运营人员核查原网关。切换网关地址不会解除这个保护；恢复原配置后继续只读同步。
- Nova 模式仅复用同一素材版本正在排队或运行的任务，不把已完成结果静默用作下一次分析缓存，因为 Nova 后台可以随时更换型号。旧分析仍可查看；点击“重新分析（计入额度）”才会重新核验远端模型并创建新任务。直接模型模式保持原有的已完成结果缓存。
- 本地请求额度是保守的任务预留量，不等于上游实际账单。Nova 还有自己的服务侧额度；两端都必须允许调用。
- 不转发 Nova 的原始错误响应，避免把内部信息或凭据显示给浏览器。

此模式只复用分析能力。它不等于已完成知识包发布、Nova 入库确认或多图项目知识整合。
