# 发布容量修复与持续 500 张的协议缺口

日期：2026-11-06。状态：本地离线代码与测试完成；本地提交信息见本轮汇总日志，未推送、未部署、未发布线上知识包。网络权限撤回后未访问网络、SSH 或 GitHub。

## 本轮完成的代码

- `knowledge/release.py` 在签名前核对每条 JSONL 大小、记录数、唯一图片合计、最终文件库存合计和最终签名 envelope 大小。源图在早期预检后改变，也会按最终暂存字节再次核对；失败时不调用签名函数、不切换 `latest.json`。
- `workbench/publishing.py` 增加与接收端相匹配的发布包预算。检查覆盖最终 full checkpoint 的历史图片及记录，不能只检查本次新增。合并 checkpoint 时先核算再复制历史图片，超限不删除旧案例。
- 同一包中相同内容图片按路径去重计费，修复以前按每条案例重复累计相同图片字节的问题。
- `auto_editorial.py` 在冻结新批次前按容量选择子集：逐条保留最大合法 JSONL 字节余量、图片按 hash 去重，未选素材留到下轮。已有冻结批次不重新拆分，已签名包继续遵守原恢复身份。原用途授权、AI 复核、下游日报配额仍分别校验，容量不是授权。
- 发布容量不足会记录固定 `publication_capacity_exceeded` / `final_release_capacity_exceeded` 状态。不能将保护性阻止发布描述为成功交付。

## 部署前必须明确的配置变化

B 本地源码 `apps/web/src/lib/inspiration/config.ts` 默认单包 **128 MiB**、单次同步 **256 MiB**。11 月 5 日现场记录中的 **256/512 MiB** 是运维覆盖配置，不是源码默认值。本轮没有网络权限，未重新核对现网。

A 新代码使用 `OMNISIGNAL_WORKBENCH_PUBLICATION_MAX_PACKAGE_MIB`，允许显式整数 1–512；省略时保守对齐 B 默认 **128 MiB**。配置非法则停止，不能静默回退无限容量。状态中用 `limit_source=receiver_default_128_mib` 或 `explicit` 区分。

**不可直接把此代码无配置替换当前运行镜像。** 旧 A 没有这个环境变量，已知存量图片约 213 MB。若直接按默认 128 MiB 启动，后续合并 checkpoint 会因超限暂停。恢复正常部署权限后，必须先确认 B 的实际包上限；若仍为 256 MiB，再显式设置 A=256，并验证真实完整 checkpoint。此配置不会修改 B，A 设置大于 B 也不能自动获得接收能力。

B 还有独立的 `records.jsonl` **128 MiB** 单文件限制；本轮 A 也会在签名前核对，不随总包上限调大。单图 20 MiB、单条记录 1 MiB、每包最多 2000 条均保留。

测试全部使用本机合成素材、隔离 SQLite 和本地签名密钥，不访问模型或外部网站。集成最终全量 **1300 passed**，保留 1 条既有 Starlette 弃用提醒。

全量检查还发现 Windows 并发创建目录时，`Path.resolve()` 偶发返回不同扩展前缀，导致同一目录被误判越界。新增仅归一标准驱动器/UNC 扩展前缀的比较；真实越界、symlink、签名私钥不得放入发布目录等约束保留。8 项确定性回归及 100 轮/200 线程压力通过，原测试的超时没有放宽。

## 为什么还不能宣称每天持续交付 500 张

本轮分批是“日常 unsigned 新增批次”的容量控制。它没有改变当前已有链达到 16 个节点后、下一次发布触发 full checkpoint 的机制。所有未撤回历史仍要进入那个 full，超过配置的 256 MiB 或 2000 条后就会暂停；不能继续只发 delta 来躲避它，因为 B 还有 32 节点链上限、整次同步字节上限。即使 A 每个包合规，B 冷启动或长时间未接收后的合并链仍可能超限。

按昨天旧样本均值估算的 500 张约 439 MiB/日不是实测产量，新来源图片分布、机器资源与模型成本仍需验收。容量保护不解决来源登录/真实分页，不扩大图片用途许可，也不将 Omni 签名数记成 DeepFlare 成功接收数。

## 最小后续协议工作包（A/B 共同升级，尚未实现）

现有 schema 2 已用于接收方范围，不能把它当作未占用版本号。容量分片应单独定义新版本或显式扩展契约，并先交付 B 的兼容读取能力，再打开 A 发布开关。

1. **签名的 checkpoint 索引**：固定 recipient、序号、根哈希、分片数和每片哈希/大小/记录范围；每片维持当前记录、文件和字节上限。索引本身也有有界大小及分页策略，不能用一个无限列表替代大包。
2. **内容寻址图片**：图片对象使用固定 hash 身份并保留来源证据，B 已验证的图片无需每个 checkpoint 重传。下载路由只能按签名白名单的相对路径访问，禁止任意 URL。
3. **B 持久化同步作业**：暂存 checkpoint、已校验分片、文件和游标；每次运行受现有字节/时间预算限制，下一次继续。冷启动全量累计可大于单次预算，但每次运行仍有界，不上调单包/单次限制来掩盖问题。
4. **完整后原子启用**：全部分片和图片核验、权限过滤、索引构建及检索抽查完成后再切活动版本。部分失败、重启、重复点击接收都保持旧版本可用。
5. **撤回与保留**：签名撤回优先检查，跨分片不丢失 tombstone；旧版本与图片清理只能发生在明确保留策略和无引用证据之后，不因扩量删除历史。

验收至少覆盖：丢片/乱序/重复片、hash/签名/recipient 篡改、连续重启续传、重复接收幂等、未完成版本不可见、撤回跨版本立即生效、旧版读取兼容、总存量超过单包与 2000 条但每次运行有界、长时间离线后冷启动恢复。涉及 B 的核心文件为 `inspiration/protocol.ts`、`replica.ts`、同步作业存储与签名内容路由；不是只改一个上限参数。
