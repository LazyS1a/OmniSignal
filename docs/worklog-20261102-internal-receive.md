# Omni自动发布与DeepFlare点击接收

日期：2026-11-02。用户明确希望AI自动发布，只在DeepFlare点击接收，日常偶尔查看Omni。该指令覆盖此前常规素材逐批确认用途的操作安排。

## 本次实现

- 独立`publication_use_grants`记录公司内部灵感库操作策略，绑定素材、修订、原图哈希、完整输入和策略版本；原素材权限、内容版本和已完成任务不改。
- 只给来源范围内、AI检查与分类有效、未明确禁止、未永久撤回的素材建立内部交付投影，生成签名包；不把模型结论记成人工审核或版权证明。
- 包带接收工作区和部署origin。DeepFlare新版在导入、继承、回滚和读取时校验范围；旧版消费者不天然理解新增字段，因此先升级B，再激活A策略。
- DeepFlare新增“接收最新灵感”，持久任务可刷新恢复；本预览使用manual内容模式，撤回继续自动同步。正常流程不需要回Omni逐张审核或手动生成包。
- A运行页显示内部用途策略；原逐图权限保留unknown时不再错误计为全部被阻断。普通编辑仍有版本保护，本轮自动用途策略走独立记录。

## 保全与验证

既有存储行/正文版本不一致素材继续阻断；不修写旧23条异常、不重提失败模型任务。签名前复读策略；图片准备过程中撤销策略会阻断签名。签名成功但SQLite回写失败按原包身份恢复，checkpoint保留历史用途依据。

专项37个新策略用例及原审核/发布回归通过；最终后端全量1069项通过（1个既有Starlette弃用提示），线上实际结果将在交付时追加。前端构建和30项灵感详情交互检查通过。模型新增付费评测0，既有20张/日新规则试运行、采集100/主分析120保持，质量缺口未因用途策略而消失。

## 部署计划

1. 推送并验证DeepFlare `claude/layer-quality`：manual内容接收、明确origin、正常登录、原10案例及新按钮。
2. A代码升级、完整源文件/原图/权限/任务/签名保全核验。
3. 根据新用户指令，原子新增`publication_authorized`有限策略，worker自然发布合格库存；helper本身不提交模型或接收任务，但开启策略会产生正常业务发布。
4. 验证真实A签名包、B正常接收入口与范围守卫。新包留给用户在DeepFlare点接收；只读查看不应暗中消费新包。

范围：现有四个来源、当前分层预览的既定品牌工作区；main和正式站不变。已有暂停跟进自动化不恢复。
