# 本地故障检查与 SQLite 恢复演练

适用范围：D 盘 OmniSignal 开发库与本机运维 API。不是 PostgreSQL 灾备手册，也不是长期运行验收报告。

## 一条命令验证数据库备份

在项目根目录的 PowerShell 中执行：

```powershell
.\scripts\test-sqlite-recovery.ps1
```

默认读取 `data/omnisignal.db`，在 `backups/sqlite/drill-<UTC时间>-<随机ID>/` 新建以下文件：

- `backup.sqlite3`：通过 SQLite 官方在线备份接口生成，包括 WAL 内已经提交的事务。
- `restored.sqlite3`：从备份恢复的独立副本，不替换原库。
- `evidence.json`：校验结果、数据库版本、表记录数、文件 SHA-256 和包含表结构/数据值的内容摘要。没有记录正文或凭证。

源库缺失时停止，不创建空源库；目标文件或它的 SQLite sidecar 已存在时拒绝覆盖。每次独立输出，不会先删上一次演练的文件。

只有命令成功且报告 `status=verified` 才算通过。校验覆盖结构版本、必需列、SQLite 完整性、外键、备份文件摘要与恢复内容一致性，不只是比较记录数。失败时保留输出供排查，但不得用这些文件恢复业务。在线复制默认最多 30 秒；完整性检查和内容摘要耗时随数据库大小增长，这不是整场演练的硬超时。

这是一份**仅数据库**备份，不包含原始归档文件、配置、代码、环境依赖或外部密钥。正式灾备必须另外备份实际配置的归档目录与配置版本，并通过安全渠道重新配置密钥。不要把 `restored.sqlite3` 直接改名覆盖线上库。

备份含历史数据：只保存在受控 D 盘目录，不提交 Git、不共享给无权限人员。当前没有自动备份计划、自动清理或异地副本。应按来源登记的保留期限管理，删除要求也必须覆盖备份生命周期。每次演练至少增加两份数据库大小的占用，空间不足时先处理容量，工具不会自动删旧文件。

## 健康检查怎么看

### 推荐：一键巡检并保存报告

在项目根目录执行：

```powershell
.\scripts\check-health.ps1
$LASTEXITCODE
```

可指定 `-Port 8010 -TimeoutSeconds 3`，目标固定为本机 `127.0.0.1`，不能传远程站点或凭据。每次只发三个 GET：`/health/live`、`/health/ready`、`/ops/summary?window_hours=24`；单项不自动重试，响应最多 64 KiB，拒绝跳转和意外压缩。超时是请求阶段/读取保护，不是整场巡检严格秒表上限。

报告独立保存到 D 盘项目 `artifacts/private/health/health-<UTC时间>-<随机ID>.json`，只含检查状态、耗时和允许的聚合计数；不写响应原文、令牌或记录正文，不覆盖旧报告。不会自动清理，需管理目录占用。不会启动服务、运行采集、改数据库或添加定时任务。

| 退出码 | 报告状态 | 含义 |
| --- | --- | --- |
| 0 | checks_passed | 本次三个检查通过；不证明长期稳定、来源新鲜度或所有运维页都可用 |
| 1 | warning | 检查通过，但近期存在停止记录，或存在创建超过 24 小时仍为 pending/running 的任务；需人工核查，不等于当前宕机 |
| 2 | failed | 至少一项不可达、HTTP 错误或响应契约不符 |
| 3 | failed | 参数、输出位置或报告写入有误；已有报告不会被覆盖 |

`transport_error` 表示连接/传输问题；`http_error` 附带 HTTP 状态码；`contract_mismatch` 表示虽有响应但状态或统计字段不符合契约；`invalid_response` 包含非法 JSON、超限或不支持的响应格式。错误响应正文不会被读取，因此 ready 的 503 在此只表明“未就绪”，不会猜测一定是 schema 还是连接故障。

`unfinished_runs_need_review` 会检查**全部历史**的 pending/running，不受最近 24 小时运行窗口过滤；只有创建超过 24 小时才提示。刚启动的正常任务不会因此报警，但刚被杀掉的任务也不会被立即判死。它按创建时间而非进程心跳计算，长任务可能正常存活，必须人工查证。新巡检需要 API 返回 `unfinished_ingestion` 字段；新旧组件未同步升级时会提示契约不符，而不是把缺失信息当 0。

服务未启动时退出码 2 是正确结果，不能为了巡检绿灯创建空库或伪造数据。查看详细健康接口可按下面方式进行。

服务运行时：

```powershell
Invoke-RestMethod http://127.0.0.1:8010/health/live
Invoke-RestMethod http://127.0.0.1:8010/health/ready
```

| 结果 | 含义 | 下一步 |
| --- | --- | --- |
| 连接失败 | API 未启动或地址/端口不对 | 核对启动窗口、进程和端口，不操作数据库文件 |
| live=alive，ready 的 dependency=database | 服务在，但数据库连接/基础查询失败 | 核对数据库服务及运行时连接配置，不把密码贴进日志 |
| live=alive，ready 的 dependency=schema | 版本不匹配、缺表/列或表读取检查失败 | 先保留备份，核对部署代码与迁移；不要手动伪造 Alembic 版本 |
| ready=ready | 当前可连接，数据库版本及运行所需表列通过检查 | 继续核查来源、运行记录和数据新鲜度 |

ready 不会自行迁移或修复数据库，也不证明所有平台可访问、后台采集持续运行或数据库约束全部正确。部署目录缺失 migrations 时启动失败；缺失来源登记文件会影响来源接口。容器已补打包来源登记，并增加 ready 健康探针；探针标记 unhealthy **不会单独触发 Docker 自动重启**，不要把 restart 策略误当故障自愈。

数据库查询错误对页面返回安全的 503，不回显 SQL、路径或数据库错误正文。数据恢复后刷新页面；缓存最长 15 秒。API client 在读取时限制响应大小，错误响应不读取正文；请求 identity 编码并拒绝意外压缩响应。反向代理如强制压缩此 API，需按这一契约配置。

容器 API 仅发布到 `127.0.0.1`，容器日志按每个服务最多 3 个、每个约 10 MB 轮转。日志轮转不是全目录容量治理，也不是安全审计保留策略；审计记录仍在数据库内。不要直接把无只读鉴权的运维接口开放到公网。

## 真正需要切换数据库时

1. 停止新增采集，确认在途任务及写入进程已经结束；来源停用只阻止后续任务。
2. 备份当前库及配套归档，记录准确文件位置和版本，保留原件。
3. 在新路径恢复并验证，用独立本地实例核对 ready、来源、标准记录、检查点和审计。
4. 经操作者确认后修改连接配置指向新库，再启动原服务；有问题先停写、恢复旧连接配置，不合并两个正在写入的数据库。
5. 记录实际丢失时间窗口、恢复耗时、补采范围和责任人。

自动演练**不执行**这些业务切换步骤。其 `elapsed_seconds` 仅为该数据规模下的复制/校验耗时，不是线上 RTO；没有定期备份和真实写入时间证据，也不能宣布 RPO 达标。

## 故障演练的验证边界

### 已验证的凭据轮换和断点恢复边界

控制面 principal 配置在创建 API 应用时加载，不是热更新。轮换时安全生成新令牌和摘要、保持 actor 身份不变、替换运行时配置并完整重启所有 API 实例；仅更改终端环境不会撤销仍运行实例中的旧令牌。新实例测试已证明：旧令牌连幂等重放也返回 401，新令牌可以取回同 actor 的既有幂等结果，版本不重复增加、审计不重复写。UI 清除旧令牌后再输入新值。该测试使用合成令牌，没有替换真实凭据，也不代表上游平台 API Key 已完成轮换。

通用 durable runner 已注入第二页采集和删除同步失败：上一批记录与检查点保留，当前未提交批次整体回滚。重新创建连接器运行后，从持久检查点补齐后续记录，再执行一次不重复插入。未知异常和协作式任务取消记为 runner_crash，并保留停止审计，不再永久显示运行中；异常原文不进入错误摘要。

上述演练使用本地合成连接器与真实 SQLite 事务，不访问外网。数据库故障导致连失败状态都无法落库，以及独立 GitHub runner 的故障路径仍需专项验证。状态修复没有在后台重试或自动重启连接器。

### 强制结束进程：已验证与仍需人工处理

独立测试子进程在两处被真正强制结束：第一批 commit 后，以及第二批 flush 但尚未 commit 时。SQLite DELETE 与 WAL 两种日志模式共四种组合均通过：完整性检查正常，仅第一批和 offset=1 检查点留存，重新运行补齐剩余两条，再次运行不重复插入。

被杀进程不能写结束时间/失败审计，因此它的旧运行记录仍为 running；系统不会伪造一条它自己并未完成的结算。超过 24 小时的未结束记录通过只读 summary/巡检提示人工核查。阈值测试使用合成历史时间，不是已经持续观测了 24 小时。

看到提示后先按运行 ID、来源和启动记录确认所有对应 worker 已退出，必要时停用来源阻止新任务，再备份并按现有连接器入口续跑。没有进程存活证明、分布式租约或 fencing，不能仅根据时长就重启/清理，以免两个 worker 同时写同一检查点。确认已退出后仍不应随手改库清掉提示；旧记录人工结算接口及可审计处理流程尚未实现。

本测试证明的是自建进程被终止后的恢复，不证明机器断电、磁盘损坏、磁盘写满或 PostgreSQL 崩溃恢复。没有终止任何用户服务、没有变更主库。

Gate 8 仍进行中：上游凭据轮换、孤立运行记录的授权结算、数据库写失败，PostgreSQL 独立恢复与重启、依赖升级回退、连续运行观测和正式告警通道仍需补验。本地单次健康巡检已完成，但不是无人值守监控。本轮没有新增计划任务、自动采集、外部通知或真实平台授权。
