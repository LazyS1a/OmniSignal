# 五个新素材来源怎么配置

核对日期：2026-11-05。目标是 Omni 获取并分析素材，DeepFlare 按实际接收的唯一图片计数，逐步从100提升到300/日。下列入口准备完成，不代表已经开启五源连续采集。

## 帅帅先做的两件事

1. 用平时的 Chrome 或 Edge 打开 Pinterest、花瓣，正常登录，确认能打开具体作品页。站酷、Behance也先确认普通作品页可打开；公开页面能读取时不强求登录。告诉小克“哪个浏览器、哪些网站已登录”即可。不要发送密码、Cookie或验证码，不需要自行开启远程调试端口。
2. 检查自己是否已有 Pexels API Key。没有则先跳过：当前 [Pexels API官网](https://www.pexels.com/api/) 明确提示暂停发放新Key；旧版文档的“立即申请”不能当作当前可用承诺。已有Key才进入下一步。

## Pexels 已有 Key 时

- 使用照片 API，不抓视频封面冒充图片素材。保留摄影师、来源作品链接和来源标识。
- 将 Key 单独存入本机私有文件，例如 `D:/coding/.novart-private/source-credentials/pexels-api-key.txt`，文件仅一行Key。它不在Git项目目录里；不要粘贴到聊天、截图、日志或提交到Git。
- 告诉小克该文件的路径即可。由小克将凭据配置到真正运行采集器的环境，验证单次搜索与少量照片下载，然后再启用计划。
- 代码支持环境变量 `OMNISIGNAL_PEXELS_API_KEY`，以及私有文件方式 `OMNISIGNAL_PEXELS_API_KEY_FILE`。有文件配置时使用私有文件读取；具体路径在服务器内必须存在且可读。
- 本机Windows文件路径不能直接传给Linux容器；部署时需要把私有文件以只读方式挂载到容器，设置容器内路径。本机存好并不等于服务器已配置。
- [官方文档](https://www.pexels.com/api/documentation/)规定请求通过Authorization头携带Key。API支持照片搜索与分页；现有实现持久化页内进度，失败不会跳过剩余图片。

## 其他四个网站

| 来源 | 当前接入方式 | 还需验证 |
|---|---|---|
| Pinterest | 正常登录页面可见Pin、具体作品元数据；已有20条本地预览样本 | 详情图片清晰度、持续浏览器会话和服务器运行方式 |
| 花瓣 | 可见采集页/作品元数据适配 | 登录、实际图片CDN及详情结构 |
| 站酷 | 普通作品页HTML/OG主图适配 | 服务器公开访问及真实作品图 |
| Behance | 普通作品页HTML/OG主图适配 | 服务器公开访问及多图项目完整性 |

本机已登录，只能证明本机浏览器能访问。若服务器需要登录，需单独完成正常授权会话部署；当前没有“把本机Cookie自动搬到服务器”的功能。遇到验证码、限流或拒绝访问时来源暂停，不绕过验证。

## 由小克负责的运行配置

- `OMNISIGNAL_WORKBENCH_VALIDATED_SOURCE_IDS`：只加入已通过真实采集验收的来源ID；不能先填满五个来伪装可用。
- `OMNISIGNAL_WORKBENCH_PUBLIC_HTML_SOURCE_IDS`：仅对实际验证普通HTTP可访问的网页来源启用，不代表已配置浏览器登录。
- 来源ID：`pinterest,zcool,huaban,behance,pexels`。缺Key或访问方式时明确阻断；已存在的四个来源保持原配置。
- 千问分析沿用现有模型配置。新源用途策略单独登记，不能因为下载成功就把旧四源授权套到新来源。
- DeepFlare接收端需先完成公司共享库正常管理员初始化、发布目标绑定，再配置自动同步和独立只读回执凭据。
- 每日接收额度从100起步，实际入库达标且有质量评估依据后再升到200、300；这不是逐张人工审核。未收到的已签名包也占发布端可用额度。

## 验收看什么

逐源检查少量真实作品：来源链接正确、图片确属该项目、尺寸达标、去重、分类结果可用、失败能停止和续跑。两端再验一次签名包接收与回执。

日报分别列采集、模型成功、质量通过、已发布、实际接收、去重和阻塞数。“每天300”指接收端首次成功入库的唯一图片；不是请求次数、下载数或模型调用数。人工审核数未知时显示未知。
